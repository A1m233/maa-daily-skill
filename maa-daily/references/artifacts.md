# 运行产物保留与容量

- 最近核验日期：2026-09-28
- 官方来源：本页为 Skill 自有组件契约，不属于 MAA 官方的日志保留机制。
- 边界：离线文件系统与假进程验证，不改变游戏业务或 MAA 原始日志。

本页只管理组件新增的报告、简报、dry-run 输出、临时 task 和隔离配置快照。策略由 `scripts/artifacts.py` 确定性执行，不要求 Agent 每轮编写清理脚本。

## 默认行为

- 产物库位于本次实际 MAA 配置目录的 `maa-daily-artifacts/`，不是 Skill 安装目录。
- `daily_run.py`、`drain_sanity.py`、`medicine_sanity.py check`、`reward_check.py scan` 默认在库内创建唯一运行子目录；`--output-dir` 可指定其他父目录，新子目录仍登记在同一产物库并计入容量。
- 日常内调用的清体力、奖励扫描及薄 runner 共用顶层运行归属，不重复计数，也不互相清理尚在使用的子报告。独立调用则拥有独立运行包。
- `run_with_evidence.py` 默认将 `evidence.json` 写入受管运行目录，以 `MAA_EVIDENCE_REPORT=` 输出报告路径。显式 `--report-file` 仍可指定新文件；包外文件只登记该文件，不接管父目录，不覆盖已有文件。需要长期自行保留的材料应另行导出，不依赖运行缓存。
- `daily_report.py` 默认仅输出到终端，不产生新文件。需要落盘时，`--output-dir` 是父目录，每次建立 `brief-*` 子目录，实际路径写入 stderr；原报告不改写。

首次写入初始化 `policy.json`：

```json
{"keep_days": 14, "max_bytes": 134217728}
```

新运行开始和顶层运行结束时自动检查。先删除已结束且超过 14 天的运行包，再按结束时间从旧到新淘汰，直到满足 128 MiB 预算；成功和已结束的失败包适用同一规则。保留天数不是最低保证，容量压力下可能提前淘汰。没有运行或清理调用时不启动后台定时器。

这是受管文件的逻辑大小预算，不是磁盘配额。当前运行和终态不确定的运行受保护，不在执行过程中截断证据；单次运行可暂时超过预算。若下一次开始时仍无法通过安全清理满足预算，组件在业务启动前拒绝新运行并报告容量问题，不无限追加。刚结束的当前包在本次收尾中保留，便于调用者读取；以后调用按策略处理。

用户需要调整策略时修改实际库内的 `policy.json`；两个字段均为正整数。Agent 不因空间不足自行扩大预算或解除保护。

## 归属与安全边界

仅清理索引与运行标记一致的已结束包；中断后仍 active、明确 uncertain、归属不一致、无法完整计量或存在符号链接/junction/reparse 的包保持受保护。不按 PID 消失或目录时间猜测可以删除，不抢占遗留锁。

包外临时文件逐个记录精确路径与内容哈希；内容已被改动时不删除。奖励扫描写入原生 tasks 目录的导航/复核 task，在对应进程结束且内容未变时立即移除，包内留副本；中断时保留。

正式 task/profile、用户资源原件、配置备份，以及 `daily_checks.py prepare` 的部署文件不属于运行包。`daily_checks.py plan --task-file` 是显式持久配置导出，同样不按运行缓存淘汰。配置快照仅略过 profiles 与 resource/tasks 下明确的配置备份，不按 `.bak` 子串删除模板或资源。

不复制、封存、轮转或删除 MAA 自己的 `asst.log`，也不处理宿主会话日志。报告仍只引用 MAA 日志区间和哈希；原日志被外部轮转或改写后，保留的报告也不保证能够重新核验。

清理问题与游戏业务结果分离：业务开始前的归属/容量检查失败会阻止执行；业务结束后的清理问题只报 stderr 警告，不把已经核验的业务成功改成失败，也不触发重跑。Agent 看见清理警告应说明，不能用它猜测招募、战斗或奖励失败。

## 查看与手动清理

```text
python <skill-root>/scripts/artifacts.py inspect --maa <本次maa可执行文件>
python <skill-root>/scripts/artifacts.py cleanup --maa <本次maa可执行文件>
python <skill-root>/scripts/artifacts.py cleanup --maa <本次maa可执行文件> --apply
```

前两条只预览，不创建策略、锁或运行包。第三条才按同一策略删除；输出列出 `would_delete` / `deleted`、容量与保护原因。独立清理是文件删除操作，须在用户授权范围内；日常组件的正常保留策略无需 Agent 逐文件弹确认。

离线管理可用 `--artifact-config <实际MAA配置目录>` 代替目录发现；不会运行 MAA。薄 runner 的自定义命令测试、简报离线导出也支持该参数。一般真实运行直接使用已核验的 `--maa` 路径，不将临时隔离配置误当成新的产物库。

库内策略或锁异常时先报告具体路径与保护原因，核对是否仍有运行者。不要删除整个库、清空 tasks 目录或伪造完成状态来绕过门禁。
