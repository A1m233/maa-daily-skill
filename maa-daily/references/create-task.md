# 创建与维护日常 task

- 最近核验日期：2026-09-07
- 官方来源：[maa-cli 配置](https://docs.maa.plus/en-us/manual/cli/config.html)
- 边界：本页负责创建流程和用户选择；运行收尾由[安全与结果](safety-and-results.md)负责，参数语义由[原生配置](native-config.md)负责。

## 先读，再问，再写

先读已有 profile/task 及其实际验证证据。正式日常优先使用最接近的成熟本地 task；无合适基线时必须读[完整参考模板](../assets/full-daily.example.toml)，只有两者均不适合才从零创建。[低风险模板](../assets/daily.toml)仅用于 smoke，不是完整日常基线。

写入前简述基线来源、继承项、变更项和未验证部分。不要因文件名带 daily 就认定成熟，也不要把模板默认值视为用户授权。已有可靠偏好直接继承并说明，不重复询问。

## 哪些事情需要问用户

只问仍缺失且会改变业务内容或资源影响的问题，不把下表当成逐项问卷。

| 选择 | 需要确认的业务含义 |
| --- | --- |
| 账号和范围 | 单账号还是固定多账号；是否共用策略，是否有账号例外 |
| 刷图目标 | 清理当前可用理智、指定场数、指定掉落数量，还是把库存补到目标；不要混为一谈 |
| 关卡和优先级 | 默认关卡、活动覆盖、按游戏日的周任务优先级；关卡关闭时停止还是改用哪个已授权关卡 |
| 恢复预算 | 不用药、普通药上限、指定临期范围；源石默认禁用，非零必须单独知情授权 |
| 剿灭 | 首次创建完整日常时主动确认是否纳入每周剿灭；纳入后的安排、目标与补跑策略见下节，不因用户未主动提及而直接省略 |
| 公招 | 是否刷新；自动确认哪些星级、保护哪些标签；是否加急及预算 |
| 基建 | 仅收产物/订单/信赖，还是换班、线索、无人机等；不要把“全部处理”直接映射为 mode 20000 |
| 商店 | 不买、优先购买还是严格只买指定商品；优先级不等于白名单 |
| 领奖范围 | 日常/周常、邮件与活动是否纳入 |
| 生命周期 | 游戏和模拟器是否保持打开；未指定时沿用可见窗口默认策略 |

设备路径、版本、开放日和配置语法优先由 Agent 检查。单场理智不是用户偏好：按[基本关卡消耗](daily-checks.md#基本关卡单场理智)查询；未收录时核对当前资源或游戏，不让模型猜数。只有不能唯一确定设备/账号、或缺少会影响下一步的业务选择时暂停提问；“有帮助”但不影响安全执行的信息不应阻塞。

库存目标任务先取得可靠库存，再算缺口；识别失败时保留未知，不能当零库存，也不能要求用户随意估一个场数。清体力算法仅供这类任务参考。

## 创建时主动讨论剿灭

首次创建完整日常时，若没有可靠的既有选择，必须主动问用户是否纳入每周剿灭；不能因为模板默认未启用就默认为不需要。已有明确偏好时继承并说明，不重复询问；用户明确只要临时刷图等窄任务时，不扩展为剿灭配置讨论。

用户选择纳入后，集中补齐尚未确定的业务选择：

- 哪个游戏日优先跑；目标是清满每周合成玉上限、限定次数，还是仅在已有扫荡券覆盖范围内运行。
- 指定日没跑或没有打满时，后续日常是否继续补齐；剿灭结束后剩余理智是否继续用于普通日常关卡。
- 使用哪张明确地图，多账号是否有例外；券不足时停止还是接受普通代理。

先说明可行方案再讨论，不要求用户理解参数名。各账号的全权委托资格、当前券库存和普通代理稳定性由 Agent 按[剿灭选关的显式语义](native-config.md#剿灭选关的显式语义)分别核验；无法核验时说明缺口，不能默认普通代理可用。周一只是模板示例，不是所有用户的固定策略；“只在周一运行”的日期条件也不等于具备后续补跑能力。选定补跑策略后，明确其配置或编排载体及未验证部分，不把业务意愿写成已实现。

## 形成可以重复调用的入口

1. 用原生 task/profile 保存选择；多账号共用业务 task，账号切换遵循[多账号流程](multi-account.md)，不要复制整套业务或另造切号 helper。
2. 静态 task 放确定参数、日期条件和顺序；运行时读取与计算使用 Skill 捆绑组件，见[日常检查与清体力](daily-checks.md)。明确哪些仍需跨进程编排。
3. 按[原生配置](native-config.md)保护已有文件、核对所有游戏日的匹配覆盖、执行当前分支 dry-run 和业务对账。语法通过不等于真实识别通过。
4. 在授权范围内做有界 smoke；未验证状态和依赖保留为未验证。交付准确的正式入口及其依赖，不把临时修补归到另一个 task 上。

创建指南不另定义运行完成标准。每次日常的结果核验与提醒，无论 task 是否由本指南创建，都按[安全与结果](safety-and-results.md)执行。
