# 创建与维护日常 task

- 最近核验日期：2026-11-02（统一首次创建默认选择；不表示新环境已通过实机验证）
- 官方来源：[maa-cli 配置](https://docs.maa.plus/en-us/manual/cli/config.html)
- 边界：本页负责创建流程和用户选择；运行收尾由[安全与结果](safety-and-results.md)负责，参数语义由[原生配置](native-config.md)负责。

## 先读已有选择，再补默认值

先读已有 profile/task 及其实际验证证据。正式日常优先使用最接近的成熟本地 task；无合适基线时必须读[完整参考模板](../assets/full-daily.example.toml)，只有两者均不适合才从零创建。[低风险模板](../assets/daily.toml)仅用于 smoke，不是完整日常基线。

选择优先级：本次明确要求 → 本机已确认的账号偏好/配置 → 下表默认值。写入前简述基线来源、继承项、采用的默认值和未验证部分。不要因文件名带 daily 就认定成熟，也不要用默认值覆盖已有偏好。用户只要求创建配置时不操作游戏；用户已要求按默认配置运行时，简短告知资源影响后按正常门禁执行，不逐项重复征求偏好。默认值不证明设备身份、关卡代理或资源部署已经可用。

## 首次创建的默认选择

本表是业务默认值的唯一说明入口。用户没有提供偏好，或说“你定”“用默认”，就按表生成并持久化；不用先要求用户逐项回答。模板用于表达参数，不从任意示例反推另一套默认值。窄任务只采用其范围内的默认值，不因本表扩展成完整日常。

| 项目 | 未指定时采用 | 落地与边界 |
| --- | --- | --- |
| 账号范围 | 当前已核验的单账号，不切换其它账号 | 已有明确多账号清单时沿用，不缩为单号；多个候选无法唯一确定才问 |
| 客户端、设备、profile | 沿用已确认环境；首次使用可唯一发现的目标 | 由 Agent 检查，模板 `Official` 不是其他服务器的默认身份，不猜设备或登录名 |
| 刷图目标 | 清理当前可用理智，默认常驻 `1-7`，不按星期轮换或覆盖活动 | 实际未解锁、代理不可用或导航失败时停止说明，不猜替代关卡；有材料/次数目标时不套清空逻辑 |
| 清体力方式与预算 | `daily_run.py` 调用统一清体力组件，最大倍率 10、累计最多 100 场、最多 5 个阶段 | 按当前理智计算批次并重读补尾；达到预算仍有理智要提醒，不无限运行或回退单倍旧入口 |
| 恢复资源 | 普通药、临期药、源石均不用 | 持久化 `mode="off"`、`medicine_expire_days=1`，后者只作原生范围的收尾检测提醒；不表示授权吃药 |
| 公招 | 领取已完成招募，最多开 4 槽，刷新可刷新标签；自动确认三星/四星 | `refresh=true`、`select=[4,5]`、`confirm=[3,4]`、`times=4`、`set_time=true`；三星/四星设 9 小时，保留五星/六星组合和支援机械，不加急；保留项须提醒 |
| 基建 | 仅总览收取产物、订单、信赖 | `mode=0`、`facility=[]`、`drones="_NotUse"`、`continue_training=false`；不换班、不处理线索/疲劳、不用无人机、不补货、不续训；不能称全部基建清空 |
| 信用商店 | 领取信用并严格只买招聘许可 | 用完整模板的 `MaaDailyCredit@MallBegin` 及配套资源；这会消耗信用，不用 `buy_first` 冒充白名单；不额外访友 |
| 领奖 | 日常/周常奖励 | `award=true`，`mail/recruit/orundum/mining/specialaccess=false`；此处 `recruit` 是 Award 的额外分支，不关闭前段 Recruit；邮件与额外活动默认不领 |
| 每周剿灭 | 不纳入新建默认日常 | 在交付摘要明确“剿灭未启用，可另行加入”，不强制弹问；已有启用策略继续保留 |
| 游戏日与失败处理 | 按已确认客户端的服务器游戏日；关卡不可用或执行失败即停止相关流程 | 不自动换关、扩大资源预算或重复已完成业务，恢复按运行指引 |
| 生命周期 | 必要时启动已确认环境，运行时模拟器可见，结束后游戏和模拟器保持打开 | 不默认重启已运行实例、不隐藏窗口、不自动关机 |
| 收尾与报告 | 核验理智、基建动作、奖励档位和临期药提醒，输出简报 | 沿用执行器和检查组件；未知或未完成照实提醒，不能为凑满每日奖励擅自加任务 |

例如可以直接告知：“按当前账号默认创建：1-7 清理现有理智，不用药和源石；公招保护高星和支援机械，基建只收取，商店只买招聘许可；领日常/周常，不领邮件，剿灭暂不启用，结束保持窗口打开。”随后继续配置，不把这段摘要变成新的强制确认问卷。

## 哪些事情需要问用户

业务偏好缺失且已有上表默认值时，不再追问。下面是用户提出定制时可讨论的维度，不是创建前必答问卷。只有目标无法唯一确定、要求相互冲突、能力或授权缺口会阻塞执行时，才补充必要问题。

| 选择 | 需要确认的业务含义 |
| --- | --- |
| 账号和范围 | 单账号还是固定多账号；是否共用策略，是否有账号例外 |
| 刷图目标 | 清理当前可用理智、指定场数、指定掉落数量，还是把库存补到目标；不要混为一谈 |
| 关卡和优先级 | 默认关卡、活动覆盖、按游戏日的周任务优先级；关卡关闭时停止还是改用哪个已授权关卡 |
| 恢复预算 | 不用药、普通药上限、指定临期范围；源石默认禁用，非零必须单独知情授权 |
| 临期药策略 | 使用还是不使用临期药（两者均收尾检测提醒）；沿用 MAA 天数定义，把选择与调用路径保存在本机，见[临期药策略](expiring-medicine.md)，不依赖会话记忆 |
| 剿灭 | 未指定时按默认不启用并告知；用户要求纳入时确认尚未确定的地图、目标与补跑范围，见下节 |
| 公招 | 是否刷新；自动确认哪些星级、保护哪些标签；是否加急及预算 |
| 基建 | 仅收产物/订单/信赖，还是换班、线索、无人机等；不要把“全部处理”直接映射为 mode 20000 |
| 商店 | 不买、优先购买还是严格只买指定商品；优先级不等于白名单 |
| 领奖范围 | 日常/周常、邮件与活动是否纳入 |
| 生命周期 | 游戏和模拟器是否保持打开；未指定时沿用可见窗口默认策略 |

设备路径、版本、开放日和配置语法优先由 Agent 检查。单场理智不是用户偏好：按[基本关卡消耗](daily-checks.md#基本关卡单场理智)查询；未收录时核对当前资源或游戏，不让模型猜数。只有不能唯一确定设备/账号、或缺少会影响下一步的业务选择时暂停提问；“有帮助”但不影响安全执行的信息不应阻塞。

库存目标任务先取得可靠库存，再算缺口；识别失败时保留未知，不能当零库存，也不能要求用户随意估一个场数。清体力算法仅供这类任务参考。

## 用户选择剿灭时

首次创建未给剿灭偏好时，按默认不启用，并把这项范围限制写入配置说明；不把默认关闭描述成用户明确拒绝剿灭。已有明确启用策略时继承，不因本表关闭。用户明确要求剿灭时不能用默认关闭代替实现；只确认执行所必需且无法从当前配置或证据取得的选择。

用户选择纳入后，集中补齐尚未确定的业务选择：

- 哪个游戏日优先跑；目标是清满每周合成玉上限、限定次数，还是仅在已有扫荡券覆盖范围内运行。
- 指定日没跑或没有打满时，后续日常是否继续补齐；剿灭结束后剩余理智是否继续用于普通日常关卡。
- 使用哪张明确地图，多账号是否有例外；券不足时停止还是接受普通代理。

先说明可行方案再讨论，不要求用户理解参数名。各账号的全权委托资格、当前券库存和普通代理稳定性由 Agent 按[剿灭选关的显式语义](native-config.md#剿灭选关的显式语义)分别核验；无法核验时说明缺口，不能默认普通代理可用。周一只是模板示例，不是所有用户的固定策略；“只在周一运行”的日期条件也不等于具备后续补跑能力。选定补跑策略后，明确其配置或编排载体及未验证部分，不把业务意愿写成已实现。

## 形成可以重复调用的入口

1. 用原生 task/profile 保存选择；多账号相同部分复用 task，差异部分单独配置。按[多账号流程](multi-account.md#本机账号配置清单)在本机持久化账号顺序和配置映射，不复制整套业务或另造切号 helper。
2. 静态 task 放确定参数、日期条件和顺序；运行时读取与计算使用 Skill 捆绑组件，见[日常检查与清体力](daily-checks.md)。明确哪些仍需跨进程编排。
   对分段日常，用[固定执行器配置](daily-execution.md)持久化已有前段、选关、清体力策略和领奖入口的引用，避免只留下自然语言执行顺序。配置不授予未来自动运行权限。
   新建默认日常从完整参考模板提取 Recruit/Custom/Infrast 为前段、Award 为收尾；单独保存选关 task（默认 `stage="1-7"`、`times=0`、`series=1`、普通药/临期药/源石参数均为 0，仅 dry-run 取关卡），并保存 `off` 用药策略。由 `daily-run.example.toml` 引用它们，外层按入口门禁处理 StartUp。不要把完整参考模板中的旧单倍 Fight 一起接入，也不要把只供 dry-run 的选关 task 当成真实战斗入口。纯原生单倍路径只在用户明确选择该方案时保留。
3. 按[原生配置](native-config.md)保护已有文件、核对所有游戏日的匹配覆盖、执行当前分支 dry-run 和业务对账。语法通过不等于真实识别通过。
4. 在授权范围内做有界 smoke；未验证状态和依赖保留为未验证。交付准确的正式入口及其依赖，不把临时修补归到另一个 task 上。

创建指南不另定义运行完成标准。每次日常的结果核验与提醒，无论 task 是否由本指南创建，都按[安全与结果](safety-and-results.md)执行。
