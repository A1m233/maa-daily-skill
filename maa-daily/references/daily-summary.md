# 日常用户简报

- 最近核验日期：2026-09-15
- 官方来源：下文 MaaCore v6.17.1 公招实现；汇报格式属于本 Skill，不是官方协议。
- 边界：本地证据回放与离线测试，不以简报重算游戏库存或代替账号核验。

本页拥有用户看到的总结格式；执行与完成判定仍由[安全与结果](safety-and-results.md)负责。详细证据必须保留，但不等于必须全部显示在聊天中。

## 默认呈现

普通日常采用「一句话结论 → 待关注项 → 合并的正常成果」。单账号通常一小段加少量列表，多账号按账号简短分组。没有待办就不造警告；不能为了字数限制丢弃真实未完成项。

有待关注项时必须放在正常成果前；不要先展开六七条成功清单，把保留/失败放到最后。已有组件生成的 brief 时优先直接采用或压缩其事实，不重新展开技术字段。只读回放用一句说明观察时间和未重跑即可，不重复整套「未调用/未修改」列表。

每条提醒回答：什么没做/未知、原因是否确定、用户需要做什么。保留、跳过、失败、未知不能混称失败。正常操作计数只作成果，诊断字段、路径、哈希、原始 ERR 和掉落清单默认放详细报告；用户追问、排障或要求证据时再展开。

示例（数值不是固定任务要求）：

> 当前账号：日常部分完成。
> - 清体力尚未核验，需要确认余量后补跑，不能重跑前段。
> - 公招保留了「某标签」，未开招；请决定是否手动处理或调整保留策略。
>
> 公招确认开招 3 次、刷新 3 次；每日合成玉和剿灭扫荡券已领。基建已观察到收取和换班，全部待办清空仍未确认。

未知要明确写未知，不能为了给出原因而猜库存不足、没有空槽、高星保护或识别失败。原始日志的错误数不是用户待办数量，多个内部告警可以合并一句保留提示，但不能据此丢掉已确认的业务缺口。

清体力核验失败但组件保留了 `battle_observation` 时，简报同时说明“日志上报完成多少场”和“仍未通过完整核验”，不能把 `completed_runs=0` 写成零场未打。理智观测带原时间，不称当前可用余额；掉落识别失败独立提醒，不猜用户操作或资源消耗。旧结果没有该字段时保持未知，不补造观察值。恢复前重新检查当前状态，不能因已核验计数为零就重跑整批。

## 公招事实提取

```text
python <skill-root>/scripts/recruit_check.py --report <本轮公招或含公招的前段runner报告>
```

只读校验原日志字节区间和哈希，分离每条 Recruit 链与每轮标签识别；提取确认开招动作、刷新事件、未解决标签组及 `RecruitPreservedTag` 指定的标签。刷新计数可每槽重置，不能取全局最大值；不把多次刷新当多个槽位，也不按固定四槽减去开招次数推断遗漏。

有明确保留事件才说明「MAA 保留该标签未开招」。只有组合星级、选标签事件或没有确认动作时，保持原因未知；不会自动修改 confirm/preserve 策略，也不自动补招。未完整执行、哈希不符、回调冲突返回 unknown 并提醒，不猜零次成功。动作统计不等于完整槽位库存。

能力依据：[MaaCore v6.17.1 AutoRecruitTask](https://github.com/MaaAssistantArknights/MaaAssistantArknights/blob/v6.17.1/src/MaaCore/Task/Miscellaneous/AutoRecruitTask.cpp) 的保留事件与跳过分支；已用同版本本地报告回放覆盖刷新、支援机械保留和确认开招。其它无法解析的日志保持未知。

## 汇总入口

`daily_run.py` 已自动提取公招结果，输出 `daily-result.json`、`brief.json` 与 `brief.md`。用户简报合并全部阶段，不允许奖励的局部 `reminder_required=false` 覆盖基建、公招、理智或阶段缺失。

```text
python <skill-root>/scripts/daily_report.py --daily-result <daily-result.json>
```

`--json` 输出机器可读事实和提醒；`--output-dir <新目录>` 保存新的简报文件，拒绝覆盖已有目录。旧日常结果没有公招明细时，可加 `--recruit-report <原公招runner报告>` 只读补入；调用者须先确认同账号、同服务器游戏日，脚本只验证游戏日与日志哈希，不把报告别名当身份凭证。

中断补跑没有完整 daily-result 时，调用已执行组件，再按本页格式合并原账号的有效结果。缺少的阶段必须保留为未完成/未知，不手工造 completed 报告或为了生成简报重跑业务。汇总不是新的执行器或自动恢复入口。

新建/迁移配置和排障有独立的信息需求：必要的配置变更、未验证范围和证据仍按安全参考说明，但不在每次普通日常机械重复全套部署过程。
