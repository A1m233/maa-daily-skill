- 最近核验日期：2026-09-14
- 官方来源：[FightTask](https://github.com/MaaAssistantArknights/MaaAssistantArknights/blob/v6.17.1/src/MaaCore/Task/Interface/FightTask.cpp)、[StageNavigationTask](https://github.com/MaaAssistantArknights/MaaAssistantArknights/blob/v6.17.1/src/MaaCore/Task/Fight/StageNavigationTask.cpp)、[ProcessTask](https://github.com/MaaAssistantArknights/MaaAssistantArknights/blob/v6.17.1/src/MaaCore/Task/ProcessTask.cpp)。

## 责任与接入

完整分段日常优先由[固定执行器](daily-execution.md)引用本组件，避免调用者漏掉整个清体力阶段。独立清体力/只导航请求仍直接使用下面的入口，不扩展为完整日常。

导航和选关复用 MAA 原生 Fight/StageNavigationTask；组件负责只导航边界、准备页核验、可靠成本、倍率循环和结果证据。不要让 Agent 手写主线/活动地图点击路径，也不要为了探测理智先打一场。

保留既有原生日常的三段职责：

1. 前段业务：公招、商店、基建、按服务器游戏日配置的优先剿灭。
2. 选关策略：原生 variants 仅供 verbose dry-run，取最终 stage；`times=0` 不是导航，禁止执行它来探路。必须有无条件默认分支，防止某游戏日没有普通关卡。
3. 收尾业务：清体力结束后最终 Award，再核验基建、奖励和提醒。

每个账号：环境及检查资源预检 → 官方切号并核验身份 → 前段 → 确认普通关卡 → 统一清体力 → 收尾检查 → 下一个账号。不重跑已有成功阶段，不把剿灭或指定材料目标当作普通清体力。

迁移前备份旧入口，明确被替换的 Fight；不能同时运行旧批量/单倍补尾与新组件。用户本地 task、profile 和调用说明不随 Skill 更新自动迁移。临期药两模式和收尾提醒的唯一契约见[临期药策略](expiring-medicine.md)。

## 可调用入口

```text
python <skill-root>/scripts/drain_sanity.py probe --stage 1-7 --profile <profile> --maa <exe> --output-dir <local>
python <skill-root>/scripts/drain_sanity.py run --stage PR-D-2 --policy <本地策略.toml> --maximum 10 --max-runs 100 --max-phases 5 --profile <profile> --maa <exe> --output-dir <local>
```

例子仅展示支持的参数形态，不授权刷芯片或默认清空其理智。run 只用于用户明确的清体力目标，材料库存/目标场次任务仅参考算法。

- `--stage`：接受普通代码，例如 1-7、PR-D-2、AP-4、活动关卡代码；规范化为大写，再由当前 MAA 决定能否导航。语法通过不代表 MAA 已收录或关卡开放。
- 剿灭、SSReopen、难度后缀、任意资源表达式及非标准玩法不接入；不能删除守卫绕过拒绝。
- `--cost`：已收录关卡从[成本表](../assets/stage-costs.json)取值；显式冲突拒绝。未收录关卡必须传入由官方资料、可靠游戏证据或用户提供的正整数成本，不能凭模型猜测。没有可靠来源就停止，不进行导航。当前不是自动 OCR 单场成本。
- `--maximum`：对应目标关卡已确认支持的最大连战倍率。参数上限 10 不代表任意关卡均支持十连。
- `--start-at prepared`：已处于目标准备页时跳过导航，但不跳过关卡、按钮与理智核验。其它值统一交给原生导航，不让 Agent 目测或猜起点；旧 home/terminal 参数保留语法兼容。
- probe 仅导航和读数；run 在其后执行统一用药/无药循环。不切号、不领奖。源石和普通药为零。

先按 [daily-checks](daily-checks.md) 部署共享检查资源；新脚本在每次调用自己的临时配置中生成目标文字节点，不为每个新关卡修改正式资源。`run` 两模式均需药物检查依赖。已有旧三关资源保留用于旧任务与历史报告兼容，不是新入口的关卡白名单。

## 原生只导航的隔离边界

当前 v6.17.1 没有独立导航参数：`times=0` 会同时关闭导航，正数 Fight 通常还会开战。组件采用如下隔离方式：

1. 在本次证据目录创建两份新的配置快照，复制当前 profiles、相关配置文件和用户资源，不改源文件。通过子进程 `MAA_CONFIG_DIR` 选择，并调用同一 maa 的 `dir config` 确认变量实际生效；不生效就在任何 dry-run/真实进程前停止。
2. 两份快照都生成 `MaaDailyCheck@VerifyStage`：目标文字来自参数，固定使用标准准备页的关卡区域。另一份仅供导航：覆盖 `FightBegin` 为无点击的 Stop，同时阻断开战与药石确认节点。已有用户同名命名空间节点也只在快照内阻断。
3. 导航快照中运行原生 `Fight(stage, times=1, series=1, 所有恢复预算=0)`，由 MAA 自己执行选关。任务预算只是使导航启用，不是授权打一场；安全边界是临时资源里的 Stop，而非运行中断或时间估计。
4. 薄 runner 必须取得完整任务链；业务核验要求原生 StageNavigationTask 完成和 FightBegin 的 Stop 被实际执行，拒绝战斗、结算或资源消耗事件。内部 ERR 保留为告警，不凭数量直接拦截，也不枚举忽略节点；SubTaskError、链错误、缺少 Stop 或选关完成证据仍拒绝。随后在**不含这些阻断覆盖**的正常快照中独立 probe，取得目标关卡及理智证据后才允许开战。独立 probe 的严格识别条件不因导航告警放宽。
5. 真正战斗不使用导航快照。禁止让 Agent 裸执行导航任务 JSON、把阻断覆盖复制回正式资源，或复用导航进程去打关。

原生节点与任务语义仍依赖 MaaCore 版本；升级后应重新验证。此方法不是“任意初始页面安全恢复”的证明：未知弹窗、登录页、在途战斗、不同主题等仍按识别失败停止。Agent 不依赖视觉操作。开始前仍须确认账号、设备、可见窗口和无并发操作者。

## 准备页与计算

`cn-standard-joint-v2` 参数化核验保持既有联合门槛：同一个有界 Custom 链内，精确目标关卡、正确“开始行动”文字及区域、两次一致理智数字；所有节点为 DoNothing。关卡候选分数 0.90，按钮与理智 0.98；低分、错位、缺节点或读数冲突均停止。旧三关证据可只读回放，新运行不再逐关维护 Verify 节点。

识别区域仍对应标准 1280×720 准备页；通用化的是关卡参数，不是任意布局。特殊关卡不满足核验时不猜测坐标、不通过放宽分数继续执行。成本表与单次实际倍率资格仍需有效。

无药阶段按 `floor(S/C)` 计算最大整批或直接余数，每个成功阶段后重读并重新计算。临期药固定倍率阶段及补尾见上述策略页，不因当前理智不足就忽略已授权恢复，也不以不足一场证明药物库存清空。

## 已知边界：博士升级恢复理智

博士升级会恢复理智，不能仅凭上涨断言用药。当前不预测升级、不识别升级弹窗；已核验正场次后，理智未下降或上涨记录 `sanity_non_decreasing`，按新读数重算。错误链、掉落识别失败或未核验场次仍停止；不以升级为理由忽略错误。总场次和阶段预算限制循环。

## 结果与复用

每个真实进程经薄 runner 保存区间哈希与内部告警。`processes.json` 记录临时 task、配置目录及导航隔离标志，原文件保留用于审计；不自动删除或中断后续跑。`result.json` 区分已核验场次、未知阶段、最新理智和药物提醒；开战后尚未重读时旧值只保留在 last_known_sanity，不用于补跑。

退出 0 表示 probe 有效，或清理完成（可能带 completed_with_reminder），不是完整日常或临期库存清空。失败保留证据，不能自动回退旧 task。扫描失败可能遗留窗口，因此仅在有终态证据时报告 prepared。

旧三关导航/联合 OCR 已有 AP-5、CE-6、LS-6 的不同起点实测和错误停止样本；旧统一用药流程另有 AP-5 固定十连后九连补尾真实样本。它们支持计算与核验基础，不证明本次新隔离导航已实测。

2026-09-14 新路径覆盖了关卡名校验、动态目标文字、配置隔离、守卫不泄漏、环境变量不生效时停止、导航完成但未阻断时拒绝，以及独立 probe 失败不进入作战等离线场景。本机 maa-cli 0.7.5 / MaaCore 6.17.1 的 1-7、PR-D-2、AP-5 导航 dry-run 可装配；这部分仅验证解析。
